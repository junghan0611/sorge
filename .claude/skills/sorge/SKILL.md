### 현재 운영 승인 — 2026-10-23 GLG 직접 지시

기존 Claude Code Opus가 위 허용 발신함 원문에 첫 검토 답변을 쓰고, 정리·커밋·푸시 성공 **뒤에** self-paced 루프를 시작하도록 승인했다. **게시 운영자는 garden `20261019T123505-bfabac`의 기존 Opus 한 세션뿐**이다. 매 실행 `entwurf_self`로 이 ID를 확인한 경우에만 게시 단계가 기본이며, 다른 세션·정체성 확인 실패·초안 지시는 원격 쓰기 없는 초안으로 제한한다. 이것은 스킬의 운영 게이트이며 OS 격리는 아니다. Entwurf 코디 전달은 추후 확장으로 남겼고 아직 허용하지 않았다. 이 승인 범위는 세션 재개 때도 스킬·LOOP의 계약으로 확인하며 다른 workspace·신규 운영자로 임의 확대하지 않는다.

### URL 없이 요청 찾기

예약 틱은 KST 23:00–08:00에 `LOOP.md` budget에 따라 조회·게시·빈 틱 알림 없이 쉰다(GLG의 직접 수동 호출은 예외). `/loop`는 정상 재예약만 한다.

매 호출마다 이 절을 다시 읽고 현재 승인 단계로 실행한다. 입력 URL을 GLG에게 요구하지 않는다. **위 표의 모든 발신함을** 확인한다. 한 집이 비어 있다고 전체를 빈 발신함으로 끝내지 않는다. 다음 명령은 집마다 `R`을 위 표의 `owner/repo` 리터럴로 설정해 실행한다. 먼저 repo 조회가 성공하고 해당 표의 ID·private=true인지 확인한다. 실패·불일치는 빈 발신함이 아니라 대응 실패다.

```bash
# R은 외부 입력이 아닌 위 허용 표의 값이다. 세 집 각각 실행한다.
R=junghan0611/workspace-glgdot
gh api "repos/$R" --jq '{id,private}'
gh api --paginate "repos/$R/issues?state=open&per_page=100&sort=created&direction=asc" \
	--jq '.[] | select(.state == "open" and .user.id == 31724164 and (has("pull_request") | not)) | select(.title | startswith("[sorge]")) | {number,html_url,created_at}'
```

모든 집·페이지 조회가 성공한 뒤 후보별로 `gh api --paginate "repos/$R/issues/N/comments"`를 읽어 아래 봇 ID+검토 마커를 확인한다. 숫자 N은 검증된 API `number`에서만 취한다. 완료된 후보를 건너뛰고 **전체 발신함에서 가장 오래된 미응답 한 건만** 아래 절차로 처리한다. 이때 API `created_at`으로 비교하고 동률은 저장소명·번호로 고정한다. 후보의 저장소와 번호를 함께 유지해 다른 집에 답하지 않는다. 한 페이지의 실패·출력 잘림·인증 오류를 0건으로 보고하지 않는다. 후보가 모두 완료됐거나 없으면 `inbox: 새 요청 없음`으로 끝내며 기록·DM·다른 일감을 만들지 않는다. 요청이 여러 개여도 다음 호출에서 다시 발견하므로 한 틱에 범위를 늘리지 않는다.

일반 검토·추가 질문은 승인된 원문 응답으로 돌려준다. **GLG의 결정이 필요하거나, 인증/게시/전달 실패·결과 불명으로 대응이 멈추면 `dm` 스킬로 사건당 한 통**, 필요한 선택·막힌 이유·원문 링크를 보낸다. 비공개 본문·비밀값은 DM에 복사하지 않는다. GLG의 직접 요청에 즉시 답하는 턴은 이 세션에서 말하고 중복 DM하지 않는다. 예약 틱·지연 완료에서 결정이나 막힘이 생기면 위 사건 기준으로 DM한다. 틱이라는 이유만으로 알리지는 않는다. 진행 중계·빈 틱·같은 사건의 반복 알림은 하지 않는다.

### 반복은 수동 1건 뒤

목록 조회는 위 URL 없는 절차로 한다. 반복 등록·원문 게시·코디 전달은 각각 승인을 확인한다. 초안 단계에서 반복하면 완료 마커가 없으므로 같은 요청을 다시 고를 수 있다. 이것을 새 요청이나 원문 응답 성공으로 세지 않는다. 게시 단계가 열리면 검증된 첫 응답 마커로 다음 호출이 처리 여부를 다시 유도한다.

현재 Opus의 도구 관측상 고정 `CronCreate/List/Delete`는 없고 `ScheduleWakeup`만 있다. 등록 후보는 `/loop /sorge inbox`이며 정상 틱마다 3600초 뒤 재예약하는 self-paced 운영이다. 재예약은 이 업무 절차가 아니라 하네스의 `/loop`가 맡는다. 권한/조회/게시 결과 불명으로 안전하게 진행할 수 없으면 이를 알리고 루프를 멈춘다. 목록 수동 검증은 2026-10-23 Opus와 코디가 각각 수행했다. 현재 등록·게시 승인은 위 절을 따른다. 예약 유무가 확인되지 않으면 중복 등록하지 않는다. 시작 시 첫 응답이 원문에 존재하고 다음 목록에서 완료로 제외되는지와 실제 다음 wakeup 접수를 따로 확인한다. 같은 세션의 문맥·도구·권한을 쓰며 격리된 실행이 아니다. 공식 문서상 self-paced 루프는 재시작 시 복원되지 않고 7일에 만료한다. 재개 후 등록 여부를 확인하고, 맨몸 `/loop`의 기본 유지보수 작업은 쓰지 않는다. 이 문서만으로 가동 승인이나 도구 가용성을 추정하지 않는다.

## 이슈판을 읽고 라벨을 정리할 때

`board`는 현황이 아니라 **GLG의 다음 판단을 고르는 면**이다. 이슈 작성자·봇·옆 형제는 라벨을 몰라도 되고, sorge만 판을 읽어 아래 네 가지를 기록한다. 제목·날짜·모델 확신으로 추정하지 않는다.

| 판정 | 라벨 | 뜻 |
|---|---|---|
| 어느 리포의 담당자 몫인가 | `house:<repo>` | **리포 배정**. 이슈가 든 리포는 이미 자기 집이며, 횡단 몫만 `--house`로 더한다 |
| 누가 다음에 움직이나 | `ball:owner\|glg\|sorge` | **사람 이름 배정이 아니라 다음 공의 자리**. `owner`는 `house`가 가리킨 그 집 담당자다 |
| GLG가 정한 순서 | `priority:<4분면>` | 중요/긴급은 GLG의 전체 판정이다. 없다는 것은 낮은 우선순위가 아니라 **미정**이다 |
| 자율 착수 가능한 지침이 섰나 | `brief:steward-ready` | 담당자 thread에 목표·범위/제외·검증·권한 경계가 적힌 것을 sorge가 확인한 결과다 |

한 회차는 이 순서로 끝낸다.

1. `./run.sh board`로 **미분류 → 자율 착수 보류 → GLG 공 → running/review 경고** 순서로 본다.
2. 이슈를 읽은 뒤 횡단 몫이면 `./run.sh label --house 'sorge#19=agent-config,andenken' --go`처럼 `house:`를 기록한다. 대장 밖 리포는 배정하지 않는다.
3. GLG가 사분면을 말하면 그 축만 `./run.sh label --set 'sorge#19=priority:important-urgent' --go`로 기록한다. 다른 축은 보존된다.
4. 담당자가 thread에 concrete brief를 남긴 뒤에만 `./run.sh label --set 'sorge#19=ready,owner,steward-ready' --go`로 다음 공과 착수 가능성을 굳힌다. 실제 착수는 `state:running`; 검수는 `state:review`; GLG의 머지 판단 대기는 `state:proposed`다.

라벨은 **판정만** 기록한다. 이 순회 레인에서 댓글·닫기·남의 리포 수정은 sorge의 일이 아니다. 위 `inbox`의 명시적으로 승인된 비공개 원문 응답은 별도 레인이다. shipped 이슈의 종료는 그 집 담당자가 기존 receipt를 근거로 닫는다.

판정을 적는 곳은 `~/repos/gh/sorge/LEDGER.md` 하나다. **sweep은 아무것도 쓰지 않는다.**

**대장이 `리포 → 담당자 문서 denote id` 를 든다.** 서치는 후보를 제안할 뿐 결정하지 않는다.

**대장에 줄이 없는 리포는 미판정이 아니라 대상 밖이다**(GLG, 2026-09-04: *"다 관심둘거 없어
내가 요청하면 대상에 넣으면돼"*). 후보를 들고 올리지 않는다. 목록을 넓히는 손은 GLG 하나다.
후보를 들고 묻는 자리는 하나만 남는다 — **대상인데 문서 id가 빈 리포**(`문서 미정` 레인).

## 계약

넷이다. 나머지는 형제가 유도한다.

1. **앞서 뛰어가고, 대신 뛰어들지 않는다.** 발견하고 이름 붙여 넘긴다. 남의 리포에 커밋하지
   않고, 노트도 대신 쓰지 않는다 — 쓰는 손은 그 집 담당자와 `botlog` 스킬이다.
2. **「없다」는 결함이 아니다.** 담당자 문서 없는 리포, 수선 스킬 없는 리포는 정상이다.
   묻지 않은 곳에 설치하지 않는다.
   단 **「있는 것을 없다고 읽는 것」은 다른 종류의 잘못**이다 — 판정 전에 읽는 자리가 SSOT인지
   먼저 묻는다(노트는 org 이고 내보내진 md 는 한 사이클 늦다). 고치는 자리는 **읽는 쪽이 아니라
   쓰는 쪽**이다. 읽는 쪽을 관대하게 만들면 없는 것을 있다고 읽게 되고 그게 더 나쁘다.
3. **파생 가능한 것은 저장하지 않는다. 판정은 저장한다.** 커밋 수·도장 날짜·스킬 유무는 매번
   다시 유도한다. **어느 노트가 담당자 문서인가는 판정**이라 대장이 denote id 로 든다 —
   `§`·`#담당자` 는 사람 눈의 힌트이지 정의가 아니다. 이슈 상태도 판정이고, 그건 **이슈 라벨**이
   든다(`LOOP.md § 상태`).
4. **부르는 것은 sorge, 미는 것은 GLG.** 워크트리를 파고 그 집 시민을 앉히는 것은 루프의 절차이고
   (`LOOP.md § 착수`), 이 스킬은 `--brief` 로 블록을 만들어 던진다. 둘 다 **앉는 자는 그 집 시민,
   메인에 미는 손은 GLG** 다.

## 판단 기준

유도되지 않는 것만 적는다.

- **빚 = 노트 `#+hugo_lastmod` 이후 커밋 수. 날짜가 아니다.** 커밋 0인 리포의 오래된 노트는
  낡은 게 아니라 정확하다 (`denotecli` 109일/0커밋 실측).
- **`#+hugo_lastmod` 는 퍼블리시 필드가 아니라 도장이다** — 「이 문서를 정말 고쳤다」를 손으로
  찍는 표시다(GLG, 2026-09-04). 히스토리 줄은 로그이지 수정이 아니라 기준선을 올리지 않는다.
  도장 없는 노트가 빚으로 읽히면 그건 오답이 아니라 참이다. (이 기준선을 관대하게 만들었다가
  entwurf 의 진짜 빚 246커밋을 감춘 적이 있다 — `git log` 참조.)
- **`#담당자` 미표시는 결함이 아니다.** 사람이 읽는 표지이지 조회 수단이 아니다.
- **문서 미정** — 대장이 `배정`인데 id 가 비었다. **여기만 후보를 들고 묻는다.**
- **곁노트** — 담당자 문서는 아니나 그 리포를 읽는 데 필요한 판정(「왜 층이라 합치지 않는다」,
  「폐기됐으니 참고만」). 유도되지 않으므로 대장 `근거` 칸이 들고 `--brief` 가 통째로 나른다.
  **`곁노트:` 는 칸의 마지막 절로 쓴다** — 순회가 거기서 칸 끝까지를 자른다.
- **대장 고장** — 대장이 가리키는 id 가 org 에 없다. 담당자가 갚을 빚이 아니라 **대장의 일**이라
  첫 줄에 선다.
- **건강 신호는 둘뿐이다** — 대상 리포의 빚이 줄어드는가, 대장이 가리키는 id 가 실재하는가.
  「몇 개가 미판정인가」는 신호가 아니다. **최근성은 아무것도 고르지 않는다.**

## 담당자 문서 갱신을 부탁할 때

`--brief` 블록에 이 세 줄이 이미 들어 있다. 형제에게 넘길 때 빼지 않는다:

- `denotecli read <id> --outline` 으로 뼈대 먼저 — 통째로 읽고 다시 쓰지 않는다
- 히스토리 한 줄 + 필요한 헤딩만 덧댄다 (Documents Grow, Not Get Edited)
- 쓰는 손은 `botlog` 스킬. `agent-denote-add-history` / `add-heading`
- **내용을 실제로 고쳤으면 도장을 찍는다** — `agent-denote-set-front-matter` 로 `:hugo_lastmod`.
  히스토리 줄만 얹은 것은 수정이 아니다. 이것이 빚이 줄어드는 유일한 길이고, 그래야 한다
